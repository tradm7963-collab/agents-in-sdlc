エージェントモードで GitHub Copilot を使うと、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行します。VS Code の Copilot Chat では、自分のコンピューター上でリアルタイムに実行されるツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、会話に追加のプロンプトを送って作業を調整できます。エディターを離れる必要はありません。

この演習では、次の内容を学習します。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集をレビューして承認する。
- セッションの途中でエージェントに指示を追加し、ハイコントラストモードとともにライトモードを追加する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティカスタムエージェントは、ハイコントラストモードを実装しています。作業中に、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも必要です。新しい会話を始める代わりに、現在のセッションに指示を追加します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。各ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を取り消してエージェントに再度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルの一覧を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライトモードの追加をエージェントに指示する

ハイコントラストモードができたら、同じ会話でライトモードの切り替え機能を追加します。同じチャットセッションを続けるため、エージェントはこれまでの作業から得たコンテキスト、変更したコンポーネント、スタイルの方針、ローカルストレージの使い方を保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはこれまでの変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが希望と異なる方向に進んだ場合 (たとえば、切り替え UI を意図しない形でリファクタリングする場合) は、チャット入力欄の横にある **Stop** を選択して停止し、補足プロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すより短時間で調整できます。追加プロンプトで、CSS の簡略化 (セレクターの重複ではなく CSS 変数を使用する)、方針の修正 (新しい切り替えを追加せず、既存の設定パネルにライトモードを加える)、範囲の拡張 (両方の切り替えにキーボードショートカットを追加する) などを依頼できます。

## 変更内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンが反映されているか、ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージへの保存などを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視して指示を追加しました。ファイル編集を確認し、変更を承認または取り消し、コンテキストを保ったまま追加プロンプトを送信して作業の範囲を広げました。

このレッスンでは、次の内容を学習しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または取り消す。
- 追加プロンプトを使って、進行中のセッションを調整する。
